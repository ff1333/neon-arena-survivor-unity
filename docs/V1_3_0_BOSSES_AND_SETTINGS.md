# v1.3.0：首领战闭环与中英文设置

日期：2026-10-05。实现和自动验证由 AI 辅助完成；不要将自动截图写成作者本人通关录像。实际测试结果见 [证据目录](test-results/v1.3.0/README.md)。

## 1. 玩起来有什么变化

第一次装满六个武器槽，当前升级选择结束后，小首领“守卫者”出现。出生前有 2 秒光圈预警。它会追击、发射扇形弹幕、标记范围攻击，并沿锁定方向冲刺。

击败守卫者直接增加两个等级，不生成需要追着拾取的首领经验物。保留现有经验进度，更新后续升级门槛；本次两次普通三选一由一次金色六选二替代，不叠加发放四次奖励。

此时暂停游戏、清理普通怪和待生成预警，出现六项金色奖励。同一项只能选一次；选第一项后仍暂停，选第二项后才恢复并预告最终首领“主宰”。最终战不再刷新普通怪，避免压力来源混乱。击败主宰立即胜利，可重玩或退出。浏览器不能由游戏关闭标签页，退出返回标题。

| 金色奖励 | 实际效果 |
| --- | --- |
| 强力伤害 | 当前全部武器伤害乘 1.4 |
| 强力攻速 | 攻击频率乘 1.3，也就是发射间隔除以 1.3 |
| 护甲 | 全部受到的伤害减少 35% |
| 生命上限 | 最大生命和当前生命各加 60，不超新的上限 |
| 持续再生 | 存活时每秒恢复 3 点生命，不会复活 |
| 强力射程 | 武器索敌半径和子弹最大飞行距离乘 1.3 |

这些是独立的金色乘区，普通伤害/攻速/射程升级到上限后仍有效。

## 2. 如何试玩

打开本工程 `Assets/Scenes/Main.unity`，点击 Unity 顶部三角形。主菜单点“设置”：默认简体中文，点 English 即切换英文；静音开关、总音量、音乐、音效分别控制，点返回保存。停止运行再进或关闭独立程序再开，确认设置保留。

点击开始，选一把初始武器；每三级优先选装配武器，直到六把。小首领刚出现时拉开距离，看到红色线或圆圈就横向离开。最终首领生命低于一半后预警更短并增加环形弹幕；不能只贴着它站定输出。

这版没有在正式包中打开快速升级。若只调试奖励界面，可用 Unity Test Runner 的 PlayMode 测试或独立程序 smoke 参数；这是受控测试，不是正式玩家难度体验。

## 3. 按这个顺序读代码

1. `Assets/Scripts/BossEncounter.cs`：负责阶段、触发条件、奖励选择和胜负衔接。画出 Collecting → MiniIntro → MiniFight → Rewards → FinalIntro → FinalFight → Victory；任意存活阶段死亡进入 Defeat。
2. `BossAgent.cs`：负责移动、攻击前摇、扇形弹幕、区域攻击、冲刺和半血强化。它不负责给经验、打开菜单。
3. `BossHazard.cs`：可复用的弹幕/区域攻击。区域等待前摇结束再判伤；弹幕使用一帧移动线段到玩家的最近距离，减少高速穿透。
4. `EnemyController.cs`：首领继续加入 EnemyRegistry，让已有 TargetSelector 和 Projectile 可以攻击。首领移动与接触不走普通怪的碰到玩家就自毁逻辑。
5. `PlayerProgress.cs`：`GrantBossLevels` 只处理两次等级增长，不触发普通 `LevelUpRequested`。解释为什么它不是随便塞一个巨大的经验值。
6. `PlayerShooter.cs`、`Health.cs`：金色武器乘区与护甲。治疗只对活着的玩家有效。
7. `PortfolioSettings.cs`、`PortfolioSettingsMenu.cs`、`LocalizedLabel.cs`：数据、设置面板、文字刷新三个职责。

不要背代码行号。用类名搜索；代码变动后行号会变。

## 4. 难度参数和局限

小首领生命 = 集齐六武器时估算 DPS × 20，限制在 4000～16000；最终首领为同一份 DPS × 50，限制在 12000～45000。估算不是实测 DPS，未计入命中率、走位和索敌竞争。最终首领使用奖励前快照，避免奖励增加伤害却同时把首领生命等比提高。

| 参数 | 守卫者 | 主宰 |
| --- | --- | --- |
| 普通追击速度 | 2.3 | 3.4 |
| 攻击前摇 | 1.05 秒 | 0.85 秒，半血后 0.65 秒 |
| 扇形弹数量 | 3 | 7，半血增加 8 发环形弹 |
| 单发弹伤害 | 18 | 28，环形弹 22 |
| 标记圆伤害 | 25 | 38 |
| 接触伤害 | 24 | 34 |

同一首领有 0.3 秒共享伤害间隔，防止同一扇形多发命中一帧秒杀。每只首领预建 48 个攻击对象；没有空闲对象时略过本次发射，不临时无限扩容。普通波次对象池继续沿用。

自动测试证明最终首领能击败受控场景下原地不动的玩家，以及提前离开圆圈可以不受伤；**不能因此宣称所有构筑都已数值平衡**。真实玩家首领耗时、护甲与回血组合强度、低端手机性能仍应通过试玩调整。

## 5. 三轮开发记录

第一轮：实现首领阶段控制、六选二、金色乘区、胜利出口；新增共享设置、本地存储和中文字体。保留原普通怪与武器系统。

第二轮：检查独立 Player 画面，发现设置滑块手柄被 Slider 拉得过长、金色卡片被旧全局美术初始化覆盖、胜利标题仍用死亡红色。分别固定手柄区域高度、排除独立首领画布、区分胜利颜色。截图工具改用显式相机渲染，并提高 UI 排序，避免测试截图中世界精灵盖住面板。

第三轮：补充出生中死亡清理、原地玩家受到致命压力、生命/再生奖励和语言音量持久化验证，再构建三平台。结果与包哈希记录在证据目录；不将工具完成状态冒充真机通过。

## 6. 本地化与声音方案

英文源文本和中文词条放在 `Resources/Localization/Strings.json`。`LocalizedLabel` 保留源文案，语言改变后重新翻译，避免从中文反向猜英文。动态 HUD 也刷新；使用 Noto Sans CJK，授权在项目根目录 `THIRD_PARTY_NOTICES.md`。

这是两语言的小型项目方案，使用最长词条优先的边界匹配。大项目应改为稳定文本 key、参数化模板和正式本地化流程；不能随意修改英文源句却不更新词条。

总音量用 `AudioListener.volume`，音乐与音效分别调整 AudioSource 音量。最终响度是总音量与分类音量相乘；静音不覆盖滑块值。音乐为程序生成的轻量环境循环，不是商业音乐素材。
