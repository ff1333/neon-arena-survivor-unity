## 问题与修复记录

### 1. Unity 生命周期方法拼写错误

**现象**

项目可以编译，但 GameManager 销毁时不会执行事件退订。

**原因**

方法写成了 `OnDestory`。这是合法的普通 C# 方法名，因此编译器不报错，但 Unity 只会自动调用准确命名的 `OnDestroy`。

**修复**

将方法更名为 `OnDestroy`，保留对 `Health.Died` 和 `EnemyController.DiedGlobally` 的退订。

**风险**

不修复时，静态事件可能保留已经销毁的 GameManager，重开后可能重复计数或访问失效对象。

### 2. 重开按键与界面提示不一致

**现象**

结算界面提示按 R 重开，代码实际监听 Enter。

**修复**

统一使用 `Keyboard.current.rKey.wasPressedThisFrame`，开始游戏继续使用 Enter。

### 3. 构建场景配置错误

**现象**

Build Profiles 原本启用 SampleScene，Main 没有作为索引 0 的构建场景。

**修复**

删除未使用的 SampleScene，在 Build Profiles 中启用 `Assets/Scenes/Main.unity` 并设为索引 0。

### 4. 升级按钮只有局部可点击

**现象**

UpgradeButton1 的白色区域大部分无法点击，只有局部可以触发升级。

**静态检查原因**

UpgradeButton1 使用顶部锚点并位于顶部 HUD 区域；其中心与 StateText 重叠。HUD 位于 UpgradePanel 后面绘制，非交互文本仍启用了 Raycast Target，因此先截获鼠标射线。

**修复方案**

- TitleText 和三个升级按钮统一使用中心锚点。
- 三个按钮的 Pos Y 分别设置为 110、0、-110。
- 非交互 TMP 文本关闭 Raycast Target。
- `ShowChoices()` 调用 `upgradePanel.transform.SetAsLastSibling()`，让升级面板显示在 HUD 上层。

**当前状态**

- [x] UpgradeController 已加入 SetAsLastSibling。
- [ ] 场景中的三个按钮已完成中心布局。
- [ ] 三个按钮的中央、左侧、右侧点击均通过。

### 5. 玩家可以离开画面

**现象**

PlayerMovement 只计算下一位置，没有边界判断。

**修复**

根据正交相机尺寸与当前宽高比计算可视边界，在 FixedUpdate 中使用 `Mathf.Clamp` 限制 Rigidbody2D 的下一位置，并保留 0.45 个世界单位的边缘余量。

**当前状态**

- [x] PlayerMovement 已加入相机边界计算。
- [ ] 16:9 下四条边的实际运行测试通过。
- [ ] 改变 Game 视图尺寸后仍不会离开画面。

### 6. 固定刷怪无法形成难度曲线

**现象**

EnemySpawner 加入随存活时间缩短的生成间隔，并在 45 秒、90 秒提高每波敌人数量，最大每波 3 只。

### 7. 界外敌人、界外击杀与不可拾取经验

**现象**

敌人围绕玩家按圆形半径生成。玩家靠近相机边缘后，敌人可能生成在不可到达区域；自动射击仍会攻击界外敌人，敌人死亡后经验物留在玩家无法到达的位置。

**根因**

工程同时使用了两套互相冲突的空间规则：玩家按固定竞技场限制，敌人却按无限世界方式在玩家周围生成。

**设计决策**

采用固定竞技场：玩家、敌人和经验物都必须位于相机可见范围。敌人在相机四条边缘内侧随机生成，并与玩家保持最低距离；子弹离开相机视口后立即回对象池。

**当前状态**

- [x] Projectile 已加入视口边界检查和出界 Release。
- [x] 所有经验物均可被玩家拾取。
- [x] 玩家靠边时不存在不可攻击敌人持续造成伤害。

### 9. 改变画面比例后 HUD 消失

**现象**

16:9 下血条、经验条、等级和击杀数显示在左上角；改变 Game 视图比例后，玩家边界会正确适配，但这些 HUD 元素跑出画面。

**静态检查原因**

Canvas Scaler 已正确使用 1920 x 1080 参考分辨率和宽高各占一半的缩放匹配。真正的问题是 HUD 父对象只有 100 x 100 且锚定在中央；其子对象再通过 `Pos X=-720`、`Pos Y=480` 等固定偏移模拟左上布局。这组坐标只会在特定尺寸下碰巧正确。

**修复方案**

- 将 HUD Rect Transform 改为横向、纵向全部拉伸，四个边距均为 0。
- HealthSlider、ExperienceSlider、LevelText、KillText 使用左上锚点和正数内边距。
- TimerText、StateText 使用顶部居中锚点。

**当前状态**

- [x] HUD 父对象已铺满 GameCanvas。
- [x] 六个 HUD 子对象已按各自屏幕边缘重新锚定。
- [x] 16:9、窄屏、宽屏下均保持可见且无重叠。

## 本轮学到的内容

- C# 编译成功不代表 Unity 生命周期函数一定会被调用。
- UI 的视觉重叠和 Raycast 顺序会造成“看得到但点不到”。
- 固定竞技场与无限滚动世界需要先选定一种空间模型，再统一玩家、敌人、子弹和掉落物的边界规则。
- 难度不仅由敌人血量决定，还取决于生成间隔、每波数量、玩家输出和移动空间。
- 测试结论与截图必须在真实运行后记录，不能根据代码存在就提前勾选。
